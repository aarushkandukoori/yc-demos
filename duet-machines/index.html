Gatewalk - replace a big model, one gate at a time

A toy simulation. Each route below is a kind of task an agent sends to a large frontier model. Fine-tune a small model on that route's traffic, let expert-written graders score it, and promote it through traffic gates only when it clears the bar with statistical confidence. If it slips later, it rolls back on its own. All data and scores here are synthetic.

Policy

Gates: Shadow (small model runs silently, 0% live) → 5% → 25% → 100%. Each gate re-grades fresh traffic. Failing the bar holds the route; a failed check at a live gate rolls it back one step.
How the toy works

Every request is graded by 3 rubric checks (like "cites the right policy clause"). A response passes only if all three pass. The frontier model passes each check at a high fixed rate. A small model's per-check skill starts lower and climbs with each fine-tuning round toward a route-specific ceiling, with diminishing returns. "Drift" simulates production traffic changing under a deployed model, so the monitor has something to catch.

The gate uses the Wilson lower confidence bound of the observed pass rate, not the raw average, so a lucky small sample cannot promote a model. Bigger samples tighten the bound, which is why raising the sample size lets borderline models through.
